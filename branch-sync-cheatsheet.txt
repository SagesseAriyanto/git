# Sync a Feature Branch with main

Use either merge (simple) or rebase (linear history). The number of commits on main doesn’t change the commands.

Option A — Merge (keeps all merge commits)

```bash
git switch feature-x
git fetch origin
git merge origin/main
# resolve conflicts, commit
git push
```

Option B — Rebase (linear, cleaner history)

```bash
git switch feature-x
git fetch origin
git rebase origin/main
# resolve conflicts, then
git rebase --continue
# push rewritten history safely
git push --force-with-lease
```

If you have uncommitted changes

```bash
git stash -u
# do one of the sync methods above
# e.g. rebase:
git fetch origin
git rebase origin/main
git stash pop
```

Tips

- Many commits on main: same process; rebase/merge more frequently to reduce conflicts.
- Team avoids history rewrites? Prefer merge. Team wants a linear history? Prefer rebase.
- After rebase, always use `--force-with-lease` (not `--force`).
- Really stale branch? You can also recreate it from the updated main and cherry-pick your work.

```bash
git switch main
git fetch origin
git pull
# create a fresh branch and bring commits across if needed
git switch -c feature-new
# cherry-pick commits you need (range or individual SHAs)
# example range: git cherry-pick <startSHA>^..<endSHA>
```
